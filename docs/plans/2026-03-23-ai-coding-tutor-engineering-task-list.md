## 1. 文档目标

本文档用于将 PRD 中的 MVP 范围拆解为可执行的研发任务列表，覆盖前端、后端和数据三个工作流，供产品、研发负责人和项目经理进行排期、分工和里程碑管理。

本文档默认基于以下技术栈：

- 前端：Next.js 16 + React 19.2 + TypeScript 5.9 + Tailwind CSS 4 + shadcn/ui
- 后端：Next.js API Routes
- 数据库 / 认证：阿里云 AnalyticDB PostgreSQL 版 Supabase
- AI 服务：Claude API
- 部署：Vercel
- 运行时：Node.js 24 Active LTS

## 2. 拆解原则

### 2.1 只围绕 MVP

只拆首版明确要做的能力，不把社区、支付、排行榜、移动端 App 等延后能力混入当前任务。

### 2.2 以用户主链路拆任务

任务优先服务以下闭环：

`访问产品 -> 登录 -> 选择工具 -> 发起学习 -> AI 拆解 -> 完成一步 -> 记录进度 -> 回来继续`

### 2.3 以交付物而不是抽象模块命名

每条任务应尽量对应：

- 一个页面
- 一个接口
- 一张表
- 一段流程
- 一个可测试能力

### 2.4 数据任务不是埋点附属项

本产品的核心价值依赖学习行为分析，因此数据结构、事件、报表口径必须独立成组。

---

## 3. 工作流划分

建议研发工作流划分为四层：

1. 基础层：项目、环境、认证、数据库底座
2. 核心层：工具选择、AI 对话、任务拆解、学习主界面
3. 增强层：进度记录、学分段位、地图、成就
4. 发布层：埋点、监控、测试、部署、内测支持

---

## 4. 里程碑建议

### Milestone 1：基础框架可运行

目标：

- 跑通 Web 项目
- 完成登录
- 建立用户基础数据

### Milestone 2：核心学习闭环可用

目标：

- 工具选择完成
- AI 导师对话可用
- 可生成并推进第一步任务

### Milestone 3：进度与激励可用

目标：

- 学习记录、任务状态、学分段位可用
- 历史恢复和基础成就页可用

### Milestone 4：可内测发布

目标：

- 埋点、错误处理、回归测试、部署和监控可用

## 11. 上线前检查清单

上线前至少确认以下事项：

1. 登录后能稳定恢复用户历史档案。
2. 工具选择后能正确生成初始学习路径。
3. AI 输出稳定包含“当前一步”。
4. 会话、任务状态、学分和段位数据一致。
5. 埋点可支持关键指标看板。
6. 对话失败、链接解析失败、登录失败均有明确兜底。
7. 内测环境可开关、可观测、可回滚。

---

## 12. 结论

MVP 的研发重点不是“功能堆满”，而是优先把学习主闭环做稳。只要前端的学习工作台、后端的教学型 AI 服务、以及数据侧的任务与成长模型三者协同跑通，这个产品就具备首轮内测和价值验证条件。

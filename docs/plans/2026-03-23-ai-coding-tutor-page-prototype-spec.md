## 1. 文档目标

本文档用于将 PRD 中的功能需求进一步落到页面层级，明确 Web MVP 的页面结构、信息层级、关键模块、交互逻辑、状态反馈与视觉方向，供产品、交互、UI、研发共同对齐。

本文档不包含高保真视觉稿，不直接替代 UI 设计稿；其目标是定义“页面应该有什么、如何组织、用户如何操作、每一步反馈是什么”。

补充说明：

- 本文档已按仓库内当前可运行前端原型校准。
- 当前真实页面为 7 个：`/`、`/login`、`/onboarding`、`/learn`、`/map`、`/achievements`、`/history`。
- 若本文档与更早的概念方案冲突，以当前前端原型、PRD 和 API 文档为准。

## 2. 设计定位

### 2.1 体验关键词

- 专业但不冷
- 轻量游戏化，但不幼稚
- 陪练感强，而不是问答工具感
- 永远清楚下一步
- 卡住时被接住

### 2.2 风格参考拆解

参考方向为 `Linear + Duolingo` 的结合，并吸收 `Gauth` 与 `Khanmigo` 在学习交互上的优点。

#### Linear 提供的部分

- 页面结构简洁、信息层级清晰
- 面板式布局，减少视觉噪音
- 强调任务状态、当前上下文、操作效率
- 排版克制，强调专业可信感

#### Duolingo 提供的部分

- 学习路径可视化
- 阶段性奖励和完成反馈
- “只做当前一步”的低压力体验
- 连续完成带来的正循环

#### Gauth / Khanmigo 提供的部分

- 对话型教学入口
- 先引导再回答的教学风格
- 针对卡点的快捷追问与提示
- 让用户感受到“AI 在陪我学”，不是“AI 在替我做”

### 2.3 视觉气质建议

- 主色基调：深色中性背景 + 1 个高识别品牌亮色作为学习反馈色
- 亮色用途：当前进度、CTA、奖励反馈、任务完成
- 组件风格：圆角中等、阴影轻、边框清晰、避免过度拟物
- 字体方向：中文优先，标题更有识别度，正文强调清晰可读

## 3. 全局交互原则

### 3.1 永远突出“当前一步”

无论在哪个页面，用户都必须能快速知道：

- 我现在在哪个阶段
- 我接下来做什么
- 做完之后会得到什么

### 3.2 主任务优先，旁支信息后置

- 页面中默认只保留一个主 CTA。
- 辅助信息如历史记录、扩展解释、知识图谱、规则说明默认弱化展示。
- 不让用户在第一次进入页面时同时面对多个并列决策。

### 3.3 AI 是教练，不是代做工具

- 对话区默认以提问、提示、拆解、反馈为主。
- 用户可请求直接示例，但系统应先尝试启发式引导。
- 当用户卡住时，优先出现“给我一点提示”“拆得更细一点”这类操作，而不是“直接给答案”。

### 3.4 反馈要即时、短促、可感知

- 任务完成时有清晰正反馈。
- 学分增长、段位变化、连续打卡等反馈应即时出现。
- 反馈时长控制在短节奏内，避免影响继续学习。

### 3.5 降低打断感

- 用户离开后再次进入，应自动回到上次学习位置。
- 对话未完成、任务未完成、等待输入等状态必须可恢复。

## 4. 全局信息架构

Web MVP 页面结构建议如下：

1. Landing Page
2. 登录/注册页
3. 新手欢迎与工具选择页
4. 学习主界面
5. 闯关地图页
6. 成就中心页
7. 历史学习页
8. 全局弹层：打卡、升级、任务完成、卡住求助

页面优先级：

- P0：Landing Page、登录/注册页、工具选择页、学习主界面
- P1：闯关地图页、成就中心页、历史记录
- P1.5：全局激励弹层与卡住求助浮层

## 5. 全局框架与导航

### 5.1 桌面端框架

MVP 建议采用三段式框架：

- 左侧：导航与路径概览
- 中间：主学习内容区
- 右侧：当前任务上下文与提示

适用页面：

- 学习主界面
- 闯关地图页
- 成就中心页

### 5.2 全局导航项

- 学习
- 路径地图
- 成就
- 历史记录
- 个人设置

说明：

- 登录后的一级导航尽量控制在 5 项以内。
- “学习”始终是默认首页和最高频入口。
- 当前前端原型中，`历史记录` 已经是独立页面入口，不再只是抽屉或侧页。

### 5.3 全局固定元素

- 顶部品牌标识
- 当前工具名称
- 当前段位与学分
- 连续学习天数
- 用户头像入口

## 6. 页面一：Landing Page

### 6.1 页面目标

- 在 5 秒内让新用户理解产品价值
- 区分于教程平台和普通 AI Chat
- 引导用户点击“免费开始”；已登录用户则展示“继续学习”并按真实学习状态分流

### 6.2 目标用户

- 第一次访问的潜在用户
- 从社媒、教程链接、朋友分享进入的用户

### 6.3 信息层级

首屏必须回答三个问题：

1. 这是什么产品
2. 为什么它比看教程更有效
3. 我现在可以怎么开始

### 6.4 页面结构

#### 模块 A：Hero 首屏

- 左侧主文案：把你收藏的 AI 编程教程，真正变成你的技能
- 辅助文案：发教程、发链接、发问题，AI 导师帮你拆解、陪练、追踪进度
- 主 CTA：访客为“免费开始”，已登录用户为“继续学习”
- 次 CTA：查看学习方式
- 右侧视觉：学习主界面预览，突出“下一步任务 + AI 导师对话 + 学分反馈”

#### 模块 B：三步工作方式

- 发入教程链接 / 文本 / 问题
- AI 导师拆解出今天只做的一步
- 完成任务并持续升级

#### 模块 C：适合谁

- 入门用户
- 有基础开发者
- 想系统化学习的人

#### 模块 D：工具生态

- 图形化工具
- CLI 工具
- 轻量在线工具

#### 模块 E：学习收益

- 不再收藏即结束
- 卡住时有陪练
- 进度可追踪
- 有成果和成就感

#### 模块 F：结尾 CTA

- 文案：从第一个可完成的 AI 编程任务开始
- CTA：立即免费开始

### 6.5 关键交互

- 首屏 CTA 悬停时强调“低门槛开始”
- 点击“查看学习方式”滚动到三步说明区域
- 工具生态卡片可 hover，但不在 Landing Page 做复杂选择

### 6.6 页面状态

- 默认态
- 滚动吸顶导航态
- CTA 点击后的注册跳转态

### 6.7 原型骨架

```text
+--------------------------------------------------------------+
| Logo                                      登录      免费开始 |
+--------------------------------------------------------------+
| 主标题                      | 产品界面预览                   |
| 副标题                      | 当前任务 / AI对话 / 学分反馈    |
| [免费开始] [查看学习方式]   |                                |
+--------------------------------------------------------------+
| 三步工作方式                                                   |
+--------------------------------------------------------------+
| 适合谁 / 覆盖工具                                               |
+--------------------------------------------------------------+
| 学习收益                                                       |
+--------------------------------------------------------------+
| 底部 CTA                                                      |
+--------------------------------------------------------------+
```

## 7. 页面二：登录 / 注册页

### 7.1 页面目标

- 用最短路径完成注册或登录
- 让用户进入学习主流程而非停留在账号流程

### 7.2 页面结构

#### 左侧

- 简短价值说明
- 用户收益要点
- 安心信息，如学习记录自动保存

#### 右侧

- 微信登录按钮
- 手机号登录入口
- 登录协议与隐私说明

### 7.3 关键交互

- 微信登录作为主 CTA
- 手机号登录作为次路径
- 登录成功后不回到首页，直接进入“欢迎与工具选择”

### 7.4 页面状态

- 默认态
- 登录中加载态
- 登录失败提示态
- 首次登录成功欢迎态

### 7.5 原型骨架

```text
+--------------------------------------------------------------+
| 学习价值说明             | 微信登录                          |
| 学习记录自动保存         | 手机号登录                        |
| 从教程到技能             | 协议说明                          |
+--------------------------------------------------------------+
```

## 8. 页面三：欢迎页与新手引导页

### 8.1 页面目标

- 帮用户快速完成第一次分层与起始路线选择
- 让用户带着明确方向进入学习主界面

### 8.2 页面定位

这是新用户首个真正建立产品心智的页面，不只是“选工具”，而是“决定你准备先用什么工具、以什么难度、用哪种方式开始训练”。

### 8.3 页面结构

#### 模块 A：欢迎标题

- 文案示例：先选一个方向，我们陪你从第一步开始
- 副文案：不用全会，先选你现在最想学的一个工具

#### 模块 B：工具卡片网格

分三组展示：

- 图形化工具：Cursor、Trae、Kiro、Windsurf、CodeBuddy
- CLI 工具：Claude Code、Codex CLI、Gemini CLI
- 轻量在线工具：Bolt.new、v0.dev、Lovable

每张卡片包含：

- 工具名
- 一句话适合人群说明
- 难度标签
- 推荐场景

#### 模块 C：用户水平快速选择

- 我是刚入门
- 我有一些开发基础
- 我想系统提升

#### 模块 D：起始学习路线选择

页面进入第 3 步后，展示两类可选路线：

1. 自学模式
2. 平台预设训练路径

自学模式固定置顶，说明用户可自行粘贴教程、代码或链接开始练习。

平台预设训练路径根据“主工具 + 当前水平”动态展示不同列表，单次显示约 `1-20` 个候选项中的有效子集。每张卡片至少包含：

- 路线名
- 路线摘要
- 预计关卡数
- 适合人群
- 训练 agent / 训练风格标签
- 前 2~3 个关卡预览

当前前端原型中，这些卡片已经稳定表达出以下关键信息：

- 路线摘要
- 预计关卡数
- 当前水平适配说明
- 陪练 agent 标签
- 预计完成时长
- 标签集合
- 前 2 至 3 个关卡预览

#### 模块 E：系统推荐提示

当用户选择工具与水平后，页面动态高亮推荐起始路线。

示例：

- 入门用户优先推荐零基础起步型路径
- 进阶用户优先推荐效率工作流或调试训练路径

#### 模块 F：确认入口

- 主 CTA：开始这条训练路径 / 进入自学模式

### 8.4 关键交互

- 第 1 步先选主工具，第 2 步选水平，第 3 步选起始路线
- 工具卡片支持单选
- 第 3 步分区展示：
  - 上方固定为自学模式
  - 下方为平台预设训练路径列表
- 当用户回退并修改工具或水平后，第 3 步路线列表即时重算
- 点击路线卡片后，底部出现“你将从哪里开始”的预告与主 CTA

### 8.5 页面状态

- 未选择工具
- 已选择工具，待选择水平
- 已选择水平，待选择路线
- 已选择路线，可继续
- 切换工具或水平后的路线重计算态

### 8.6 原型骨架

```text
+--------------------------------------------------------------+
| 欢迎标题                                                      |
| 先选一个方向，我们陪你从第一步开始                            |
+--------------------------------------------------------------+
| 工具选择: [Cursor] [Trae] [Claude Code] ...                  |
+--------------------------------------------------------------+
| 水平选择: [刚入门] [有基础] [系统提升]                        |
+--------------------------------------------------------------+
| 自学模式                                                      |
| 粘贴教程 / 代码 / 链接，AI 帮你拆成当前这一步                  |
+--------------------------------------------------------------+
| 平台训练路径                                                  |
| [零基础起步营] [Prompt 入门闯关] [调试训练] ...               |
+--------------------------------------------------------------+
| 你将从这里开始：第 1 关 -> 第 2 关 -> 第 3 关                  |
|                                              [开始这条训练路径] |
+--------------------------------------------------------------+
```

## 9. 页面四：学习主界面

### 9.1 页面目标

这是产品最核心的页面。用户应该在这里完成以下闭环：

- 输入教程、问题或代码片段
- 获得 AI 导师拆解的“当前一步”
- 执行并反馈结果
- 被引导到下一步

### 9.2 页面布局

采用三栏结构。

#### 左侧栏：路径与个人状态

- 全局导航
- 当前学习工具
- 当前学分与段位
- 连续打卡天数
- 历史记录入口

#### 中间主区：AI 导师对话区

这是主操作区，应占据视觉中心。

包含：

- 顶部继续学习摘要
- 顶部当前任务标题
- 对话消息流
- 快捷操作按钮
- 输入框
- 粘贴输入入口

#### 右侧栏：当前上下文面板

- 当前这一步
- 为什么先做这一步
- 当前这一步的完成标准
- 遇到问题时的提示
- 下一步预告

### 9.3 对话区模块说明

#### 模块 A：任务标题条

包含：

- 当前任务名称
- 当前任务所在关卡
- 状态标签：进行中 / 已完成 / 卡住

#### 模块 B：AI 导师欢迎消息

首次进入时默认不是空白输入框，而是 AI 主动开场。

示例：

> 我们先不急着做完整项目，今天先完成第一步：让你熟悉 Cursor 的基本工作区。你先告诉我，你现在已经安装好了吗？

#### 模块 C：快捷追问按钮

参考 Gauth / Khanmigo 的低门槛交互，首屏默认给 3 至 4 个按钮：

- 帮我拆得更细一点
- 我卡住了
- 给我一个例子
- 我已经做完了

#### 模块 D：输入区

支持：

- 文本输入
- 粘贴链接
- 粘贴代码片段

可预留但不要求 MVP 首期后端强制支持：

- 截图或图片附件入口

占位文案示例：

> 把教程链接、代码片段或你卡住的问题发给我

### 9.4 关键交互规则

#### 交互规则 1：默认先给“下一步”

AI 的第一屏输出，默认应包含：

- 当前目标
- 当前一步
- 为什么先做这一步

#### 交互规则 2：用户完成后有即时强化

用户点击“我已经做完了”后：

- 弹出轻量完成反馈
- 学分增加
- 对话流中出现“你刚刚学会了什么”
- 自动出现下一步

#### 交互规则 3：卡住时优先给分层帮助

点击“我卡住了”后，浮出三种求助层级：

- 给我一个提示
- 帮我缩小问题范围
- 给我一个最小可运行示例

不默认出现“直接给最终答案”。

#### 交互规则 4：返回时续接上下文

用户再次进入页面时：

- 恢复最后一次对话位置
- 顶部显示“继续上次学习”
- 右侧面板仍显示当前任务和完成标准

### 9.5 页面状态

- 首次进入空态
- 有任务进行中
- AI 正在思考
- 用户卡住求助态
- 任务完成反馈态
- 会话恢复态
- 对话失败重试态

### 9.6 原型骨架

```text
+--------------------------------------------------------------------------------+
| Logo | 学习 | 路径地图 | 成就 | 历史 | 学分 320 | AI学徒 | 3天连续              |
+--------------------------------------------------------------------------------+
| 当前路径/任务      | 当前任务：用AI生成第一个页面         | 当前这一步            |
| - 第1关 已完成     |--------------------------------------| - 完成标准            |
| - 第2关 已完成     | AI: 今天先只做一步...                | - 知识点              |
| - 第3关 进行中     | 用户: 我已经装好了                   | - 常见卡点            |
| - 第4关 未开始     | AI: 很好，下一步请你...              | - 下一步预告          |
|                    | [拆得更细] [我卡住了] [给个例子]      |                       |
|                    |--------------------------------------|                       |
|                    | 输入框: 发教程链接/代码/问题           |                       |
+--------------------------------------------------------------------------------+
```

## 10. 页面五：闯关地图页

### 10.1 页面目标

- 帮用户建立整体进度感
- 强化“我在持续前进”的认知
- 用路径视图替代抽象列表
- 只服务当前激活学习计划的推进

### 10.2 页面结构

#### 模块 A：路径总览

- 当前工具名称
- 当前学习计划名称
- 当前学习计划摘要
- 已完成任务数 / 总任务数
- 当前进度百分比

#### 模块 B：地图主区域

采用纵向线性关卡串联，借鉴 Duolingo 的路径浏览方式，但整体视觉更克制。

每个节点展示：

- 节点标题
- 简短学习摘要
- XP 奖励
- 预计用时

状态区分：

- 已完成 `done`
- 当前进行中 `current`
- 未解锁 `locked`

#### 模块 C：节点详情侧板

点击节点后显示：

- 本关要学什么
- 为什么当前先做这一步
- 完成条件
- 涉及知识点
- 常见误区
- 进入学习或查看复盘按钮

### 10.3 关键交互

- 点击当前关卡，进入学习主界面对应上下文
- 点击已完成关卡，查看回顾摘要并进入复盘
- 未解锁关卡可看标题但不可进入
- 页面不承担多个学习计划的切换与分发

### 10.4 页面状态

- 首次进入地图

## 12. 页面七：历史学习页

### 12.1 页面目标

- 让用户回顾自己参与过的学习计划，而不是只看零散对话
- 明确区分进行中、已中断、已完成、已放弃四类历史状态
- 为“继续当前计划”与“回顾已完成计划”提供稳定入口

### 12.2 页面结构

#### 模块 A：页面头部

- 页面标题
- 学习计划总数
- 一句话说明

#### 模块 B：学习计划列表

每张卡片至少包含：

- 计划名称
- 计划摘要
- 工具名称
- 学习水平
- 模式类型
- 完成进度
- XP 收益
- 创建时间 / 最近更新时间
- 状态标签

#### 模块 C：右侧辅助信息

- FAQ
- 学习记录保存说明
- 继续学习入口

### 12.3 关键交互

- 进行中计划默认强调“继续学习”
- 已中断计划默认强调“重新激活”
- 已完成计划默认强调“查看回顾”
- 已放弃计划保持可见，但弱于进行中与已完成计划
- 页面右上角提供主动作：有 `active` 计划时显示“继续当前计划”，无 `active` 计划时显示“新增学习计划”
- 页面主对象是“学习计划实例列表”，不是“最近消息列表”

- 有历史记录
- 为空态
- 筛选后无结果

## 13. 全局组件与弹层说明

### 13.1 任务完成弹层

出现时机：

- 用户完成当前任务步骤后

包含内容：

- 完成提示文案
- 本次获得学分
- 你刚学会了什么
- 下一步 CTA

体验要求：

- 反馈轻快，不遮挡太久
- 可 1 次点击返回主学习流

### 13.2 每日打卡弹层

出现时机：

- 用户当天首次完成有效学习行为

包含内容：

- 今日已打卡
- 当前连续打卡天数
- 学分奖励

### 13.3 卡住求助浮层

出现时机：

- 用户点击“我卡住了”

分 3 个层级动作：

- 给我一点提示
- 帮我拆得更细
- 给我最小示例

### 13.4 升级弹层

出现时机：

- 学分达到新段位

包含内容：

- 新段位名称
- 新段位含义
- 可继续挑战的下一目标

## 14. 关键页面状态与异常场景

### 14.1 空状态

适用于：

- 新注册用户尚未开始学习
- 某工具路径尚无历史记录

设计要求：

- 不出现纯空白
- 直接告诉用户“第一步做什么”

### 14.2 加载状态

适用于：

- AI 正在拆解教程
- 页面恢复历史进度

设计要求：

- 用教学型加载文案，而不是单纯 spinner

示例：

- 正在帮你拆出今天最合适的一步
- 正在回到你上次卡住的位置

### 14.3 出错状态

适用于：

- AI 响应失败
- 链接解析失败
- 登录失败

设计要求：

- 说明发生了什么
- 给明确下一步
- 保留重试入口

### 14.4 中断恢复状态

适用于：

- 用户离开一段时间后返回

设计要求：

- 页面顶部显示“继续上次学习”
- 给出上次停留任务的摘要
- 当前真实业务规则补充：连续 7 天无学习行为后，原 `active` 计划自动转为 `interrupted`；用户可在 `/history` 中重新激活

## 15. 文案与语气建议

### 15.1 总体语气

- 像专业教练，不像客服
- 像陪你一起做，不像高高在上地解释
- 简洁、明确、鼓励行动

### 15.2 推荐文案风格

适合：

- 我们先只做这一步
- 你现在不需要一次搞懂全部
- 如果卡住了，我可以先给你一点提示
- 做完这一小步，你就掌握了一个关键动作

不适合：

- 一次性输出大段教程
- 过度夸张的打鸡血语言
- 过强的命令式表达

## 16. MVP 设计取舍建议

为保证首版体验聚焦，建议做以下取舍：

### 必做

- Landing Page 明确价值主张
- 工具选择页建立学习分层
- 学习主界面打磨成核心体验
- 闯关地图体现进度
- 成就页提供基础成长反馈

### 可简化

- 成就页优先展示段位、统计、打卡和徽章，复杂技能图谱可延后
- 路径地图先用线性结构，不做多分支
- 分享卡片先保留入口，不做复杂编辑

### 不建议首版做重

- 社区互动
- 排行榜竞争
- 复杂社交关系
- 过多动画与音效

## 18. 结论

这套页面原型的核心不是做一个“更好看的聊天产品”，而是把学习路径、AI 导师、任务推进和正反馈组合成一个连续体验。视觉上要克制、专业、可信；交互上要轻、顺、低压力；产品感知上要让用户始终觉得：

- 我知道自己在做什么
- 我知道下一步做什么
- 我卡住时有人接住我
- 我正在真实进步

这就是该产品在页面层面的核心体验目标。

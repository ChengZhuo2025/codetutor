## 详细记录

### 1. 需求与决策记录

- 用户反馈：微信/抖音扫码登录未绑定账号时进入绑定手机号页，验证码正确后点击绑定仍报错，不能进入首页。
- 用户反馈：已注册用户扫码授权后进入“是否获取头像和昵称”页面，选择后点击仍返回登录界面，不能正确进入首页。
- 用户补充：服务器端扫码登录成功进入获取头像昵称弹框后，点击同步头像昵称会回跳到本地 `localhost:3000` 链接，而不是继续停留在服务器域名。
- 用户补充：新用户通过微信/抖音扫码授权后进入绑定手机号流程，输入正确验证码后仍出现登录失败。
- 认证链路属于高风险改动，先按已确认计划定位根因、补测试，再修改。

### 2. 操作描述

- 已读取登录页、OAuth callback、认证 route handler、服务层、请求鉴权与路由守卫。
- 发现用户端受保护路由只检查 `app-user-session` cookie；该 cookie 由 `POST /api/auth/login` 成功后写入。
- 根因：OAuth callback 弹窗完成业务登录/绑定后，父登录页只按消息跳转，没有重新确认业务登录 cookie；头像昵称同步也依赖隐式浏览器 session，容易在 callback 场景下丢鉴权。
- 补充根因：原先生产域名兜底修复只覆盖 `localhost` 上带 `#access_token` 的旧式 token fragment 回调，没有覆盖 Supabase PKCE `?code=` 回调；当 Supabase/Site URL 配置回落到 `localhost:3000/auth/callback?code=...` 时，头像同步后相对跳转会留在本地域名。
- 补充根因：OAuth 未绑定手机号时 callback 会尝试删除 Supabase 创建的 OAuth-only 临时用户，但之前把 `/api/auth/oauth-temp-user/discard` 失败完全吞掉，仍通知父窗口进入手机号验证码绑定；此时第三方 identity 仍被临时用户占用，正确验证码后的 `linkIdentity` 会失败。父窗口在绑定完成消息缺少 `accessToken` 时还会静默回退到当前浏览器 session，可能重新夹带旧 OAuth-only session。

### 3. 需求分析

- 绑定手机号后应保证业务登录已完成并写入用户端 cookie，再进入受保护页面。
- 已绑定 OAuth 登录应保证 `/api/auth/login` 写 cookie 后，头像昵称同步流程不会丢失继续跳转/通知父窗口。
- 新用户 OAuth 绑定手机号时，必须先成功删除 OAuth-only 临时用户，再让用户进入手机号验证码绑定；绑定完成消息必须携带 callback 产生的新 access token，禁止回退到旧浏览器 session。
- 修复需同时覆盖微信与抖音，因为两者共享 provider 抽象。
